- `research-round`: investigate the question; prove every claim with a tool call (query, trace, file, run), never from memory. Save notes with `factory file put r<n>.md` (the job's files live in the factory DB).
- `artifact`: one HTML page with the findings (the `/visual-report` or `lavish` skill), saved in the workspace, written for a colleague who has not followed the research (say what each limit means in practice); when it compares options, it shows their raw outputs side by side on at least five examples. Stef annotates it. When he asks for it on claude.ai, publish or update it as a private artifact with the Artifact tool; never Backyard, Slack or a share link.
- `gate:feedback` repeats: each round ends at the gate; Stef's feedback starts the next `research-round` (plan it with `factory plan add research-round artifact --label "round <n>: <question>"`). He accepts with "accepted"; record it with `factory gate decided feedback accepted --words "<his words>"`.
- `next-jobs`: start only the jobs Stef asks for in his words at the gate; when his accept names none, mark the step skipped and start nothing. Send each one he named to GLaDOS with `factory message --to glados "<text>"` (she runs on the server; the factory delivers it there): the brief with the artifact path, the type, the machine if Stef named one, `parent: <this job's slug>` and `why: <what triggered it>`. Tell Stef which jobs you asked for.

## Projects
In a `project` job you lead the whole project, not one piece of it: the brief is the project's goal, and every job under "Jobs under this one" in `factory job start` is part of it, each run by its own lead. Keep the project's PLAN.md current, see what each child is doing with `factory job show --job <slug>`, ask GLaDOS for the next jobs as earlier ones land, and tell Stef where the project stands as a whole. Never do a child's steps yourself; work for a child goes to it with `factory message --job <slug> "<text>"`. Code work on a PR never runs in the project's own ledger, even for a PR the brief lists: ask GLaDOS for a child `work` job with `--app <repo>:<free port>` so it has its own worktree; the brief names the PR and branch, never a worktree path in this workspace; once the child exists, `factory pr add <url> --job <child> --move` moves an existing PR to it. Research, review drafts and PLAN.md stay yours.
